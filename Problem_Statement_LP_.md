## Problem Statement
Physics-based soil moisture retrieval from satellite observations, such as the NASA-ISRO Synthetic Aperture Radar (NISAR), requires ancillary inputs—vegetation water content, land cover classification (e.g., MODIS MCD12Q1), and surface roughness—that no single archive provides. Each product comes from a different provider (NASA Earthdata, USDA, USGS), each with its own access protocol, spatial and temporal resolution, and file format. Assembling a correctly aligned ancillary dataset therefore becomes a long list of manual tasks: downloading, reprojecting, and resampling every input by hand to match the sensor's grid, and repeating that work for every new area of interest and multi-year study period.

For researchers running the NISAR soil-moisture retrieval algorithm on new areas of interest, this manual preparation creates a severe bottleneck. Processing a typical campaign requires gathering data for thousands of grid cells across multi-year dates from multiple distinct providers, easily consuming multiple hours per study area in data wrangling alone. While existing tools like Google Earth Engine, earthaccess, or AppEEARS automate large parts of Earth observation workflows, they are insufficient for this use case due to the strict requirement for offline, on-premise processing and exact alignment with the unique NISAR spatial grid.

Without an automated process, this workflow severely limits productivity and the scope of feasible studies. Solving this requires a dedicated ancillary data pipeline that outputs a standardized, co-registered format (such as NetCDF) for the target area and timeframe. To be successful, this tool must fully automate the download, parsing, and resampling steps while implementing smart local caching—ensuring data reproducibility and allowing offline re-extraction when retrieval algorithms change, without forcing redundant downloads on every revision.
